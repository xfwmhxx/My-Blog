关于第一次使用github Page遇到的一些坑...

PS: 第一次部署直接搞到凌晨4点多...以前没怎么玩过github，有点陌生（悲）

1.GitHub Pages 简介 ​

GitHub Pages 是一种用于托管静态网站的服务，用户可以从 GitHub 上的仓库中直接发布网页。它支持自定义域名，并能够使用 Jekyll 等静态站点生成器。

主要特性 ​

  • 免费托管：GitHub Pages 是免费的，适合个人和项目的网站。
  • 自定义域名：可以使用自己的域名。
  • 支持 Jekyll：可以使用 Jekyll 进行静态网站生成，方便管理博客和文档。
  • HTTPS 支持：自动提供 HTTPS 以确保安全性。

创建 GitHub Pages ​

  1. 创建仓库：

    • 在 GitHub 上创建一个新的仓库，命名为 username.github.io，其中 username 是你的 GitHub 用户名。

    当然仓库名称没有强制要求，也可以随便取，不过这样的话后面部署后github page给你生成的网址也会长一点

  2. 添加文件：

    • 在仓库中添加一个 index.html 文件，或者你可以使用 Markdown 文件（如 README.md）作为主页。

  3. 启用 GitHub Pages：

    • 进入仓库的设置页面，向下滚动到 "GitHub Pages" 部分。
    • 选择分支（通常是 main 或 gh-pages），然后点击保存。

  4. 访问你的页面：

    • 通过 https://username.github.io 访问你的网站。

使用 Markdown ​

在 GitHub Pages 中，你可以使用 Markdown 文件来创建内容。Markdown 是一种轻量级标记语言，方便书写格式化文本。

2.将前端项目部署到 GitHub Pages ​

当然，除了以上的用法外，我觉得其最强大的一点就是可以帮忙托管你的前端项目！ 以下是将你的前端项目部署到 GitHub Pages 的步骤。

步骤 1: 创建 GitHub 仓库 ​

  1. 登录到你的 GitHub 账户。
  2. 点击右上角的 + 按钮，然后选择 New repository。
  3. 输入仓库名称（可取为 username.github.io，其中 username 是你的 GitHub 用户名），选择 Public，然后点击 Create repository。

同样的，这里的仓库名其实没有强制要求，不过按照这里写的来最方便。

步骤 2: 准备项目 ​

  1. 在你的本地机器上，创建或打开你的前端项目。
  2. 确保项目中有一个主入口文件，通常是 index.html。

像Vue、React这样的框架则需要先打包，打包后自然会有一个index.html。

步骤 3: 初始化 Git ​

  1. 在项目根目录下打开终端。
  2. 初始化 Git 仓库：
bash
git init
1
  1. 添加远程仓库:

这里的repository是你的仓库名称。

bash
git remote add origin https://github.com/username/repository.git
1

步骤 4: 添加和提交文件 ​

  1. 添加所有文件到 Git：
bash
git add .
1
  1. 提交更改：
bash
git commit -m "Initial commit"
1

步骤 5: 部署到 GitHub Pages ​

  1. 在终端中，将代码推送到 GitHub：
bash
git push -u origin main
1

注意：如果使用的是 master 分支，请替换为 master。

  1. 进入 GitHub 仓库，点击 Settings。
  2. 向下滚动到 GitHub Pages 部分。
  3. 在 Source 下拉菜单中选择 main 或 gh-pages 分支，然后点击 Save。

步骤 6: 访问你的 GitHub Pages ​

  • 访问 https://username.github.io 查看你的网站。

注意：点击完Save后需要等一会，网站才会部署上去，需要等待一段时间(<3分钟)

3.踩坑经历 ​

前文也说了，没经验，所以开始时第一步创建仓库时是自己起的名称My-Blog。

以下是我的踩坑经历总结(我部署的是vitepress)

1.仓库名称自定义 ​

  1. 设置base参数

如果是像我一样仓库名称自定义的话(这里拿My-Blog为例)，则在项目打包前需要而外做一件事情，就是在config.mts文件的默认导出中加一项base。

mts
base: '/My-Blog/' # 也就是/你自定义的仓库名称/
1

因为前文说过了，如果自定义仓库名称的话会导致github page部署完之后给你返回的网址长度更长（也就是在上文标准版的前提下再加上你的自定义仓库名称作为后缀）

  • 标准操作的访问路由： https://username.github.io
  • 自定义仓库名称的访问路由：https://username.github.io/repository/

2.静态资源路径问题 ​

由于base路径改变，所有静态资源引用都需要调整：

mts
// 错误写法（部署后会404）
![图片](/public/image.png)

// 正确写法（使用绝对路径）
![图片](/My-Blog/public/image.png)

markdown

4.准备项目 ​

bash
npm run dev
1

执行完后会在.vitepress目录下生成一个dist 文件。

5.上传文件 ​

这里因为个人原因我选择只上传dist而不是上传整个源码+打包文件。

  1. 到dist目录下
bash
cd .vitepress/dist
1
  1. ​​初始化 Git 仓库​​
bash
git init
1
  1. ​​关联远程仓库​​
bash
git remote add origin https://github.com/你的用户名/仓库名.git
1
  1. ​​创建并切换到 gh-pages 分支​​
bash
git checkout -b gh-pages  # 创建并切换分支
1
  1. ​​提交所有文件​​
bash
git add .
git commit -m "首次部署"
1
2
  1. ​​强制推送到远程​​
bash
git push -f origin gh-pages  # 首次推送需要-f
1

后面不需要再操作了，github page会自动帮我部署，直接等待github page给我部署后的链接就行。
